> 操作本仓库的硬性规则——无论人还是 AI。规则中凡标注 *must*（必须）之处，违反即构成事故，须记录到 `ops/OPS-LOG.md`。

## 1. 核心原则

1. **一个路径一个写手。** 任何文件在同一时间只有一个写手（人、agent 或主脑）。并行写手通过显式交接协作，绝不双方同时编辑。
2. **每条论断都带证据分级。** `[自述]` / `[史料]` / `[研究]` / `[归纳]` / `[推测]`；引文必须带来源。查不到就写「未找到（已查: …）」——绝不静默填补空白。
3. **没有检查，就没有论断。** 能力在实验或脚本跑通之前都是 `[UNVERIFIED]`。「完成」要求有可运行的验证（一条命令，或一个第三方能复跑的文件）。
4. **状态权威。** `ops/GOALS.md` 是工作状态的唯一事实来源。`ops/OPS-LOG.md` 是只追加的历史。派发板只是快照；板与盘不一致时，**以盘为准**——说出来并更正板。
5. **指针，而非副本。** skill（技能包）与索引只引用知识文件；绝不复制内容。内容只存在一个地方。

## 2. Agent 操作协议

- **任务书格式**（委派工作）：`# Target`（范围内文件）· `# Change`（步骤）· `# Acceptance`（可观察、可检查）· 纪律说明。一份任务书一个写手。
- **回执格式**：每个工作项以回执收尾——改了什么、产物路径、原始验证输出，以及四段自审（先行产出 / 反驳 / 机械验证 / 小结）。完成情况写在回执里，而不是去改写目标。
- **禁止写入**（除任务书明确授权外）：`ops/GOALS.md`、`ops/OPS-LOG.md`、机器级板、仓库之外的任何路径。
- **预算**：每份任务书有软性工具调用预算；到达上限时，落盘当前最佳状态并列出缺口。绝不空转。
- **两种失败处置模式**（已验证）：
  - *零产出超时*（例如某通道超时且无产物）→ 换通道重派、拆得更小。
  - *运行中崩溃、已有部分产物* → **恢复同一会话**；先核已落盘产物；未经检查绝不从空白状态重开。

## 3. 研究协议

- 优先一手来源（作品、书信、论著、博物馆记录、档案）。档案的每一节都标注分级。
- 引文：逐字照录，带来源（书/信/URL + 已知日期）。引文的机翻必须标注为翻译。
- 蒸馏**操作规则**（「什么可以被执行」），而非内心状态：原则是从证据归纳出来的，不是对艺术家思想的断言。
- 新领域遵循注册契约（`docs/ARCHITECTURE.md` §3.2）：卡片 + 索引 + 冲突 + 输出映射 + 强度 + 证据，齐备后才能 `status: active`。

## 4. 验证协议

- 每个实验都随附验证器脚本；验收 = 验证器通过，且原始输出已粘贴进回执。
- **独立评审**：产物由未参与生产的 agent 评审，且使用*干净上下文*（不带过程叙述——只有产物 + 评审标准）。评审不得注水；「无法验证」是有效结论。
- **确定性契约**（动画/代码输出）：`templates/determinism_contract.md` 的 C1–C10，其中包括**乱序重渲检查**——顺序重渲会掩盖状态 bug；务必重渲一组非连续帧并比对帧哈希。
- Blender 输出：除非证明逐位一致，诚实上限就是 P1 确定性说明（EEVEE 采样噪声界）。
- 三处同步规则：蒸馏事实变化时，先更新事实来源，再更新引用它的派生产物（例如：冲突清单 → 风格卡 → 实验设计）。

## 5. 组合与冲突协议

- 组合两个模块必须按顺序走完整预检：冲突表扫描 → near-miss 显式取值 → N1 反约束重算 → N3 轴归属（辅助冲突行**整行移除**，绝不降级）→ N4 拆分裁定（同一像素统计 → 二选一；区域可分 → 分区表 + 蒙版）→ N9 验收（主模块全套 + 辅助模块的非冲突轴；冲突轴上「双重标准」即失败）。
- 禁止无声妥协：每次合并要么保留其中一方，要么对画面分区，要么按已记录的句式改写冲突条款。
- 权威文件：`knowledge/cross/conflicts.md`（C-01–C-18、N1–N9）。

## 6. 图像通道协议

- 通道：网关直连 API；**裸模型名** `grok-imagine-image-2.0`（在此路径加 `buddyfarm/` 前缀会 404——与 CLI 相反）。请求 1024×1536；实际返回 768×1152。
- 该通道**没有负向提示参数**：负向段落在请求记录中存档，但从不发送。
- 存档契约：`req` / `resp` / 图像 + `sha256` 清单。可追溯、不可复现（无种子）——绝不承诺可复现。
- 细节与探针证据：`knowledge/cross/image_channel.md`。

## 7. skill 交互协议

- skill 收到设计请求后的第一个动作是**首问包**（3+2 项；默认项明确说出；≤3 轮）。允许 opt-out（「直接做吧」），但必须用一行假设清单记录在案。
- 视觉决策需要**可见**候选（2–3 个），且展示后硬性停止。`design-brief.md` gate 文件记录意图 / 非目标 / 约束 / 用户的原话选择 / 假设 / 批准范围。批准只覆盖实际展示过的内容。
- 完整协议：`skills/designers-brain/SKILL.md`；理由：`docs/skill/skill_spec.md`。

## 8. Git 与发布协议

- 提交信息：英文、祈使句、不署 AI 名。`commit` 自由；**push 前必须通过三项检查**并在回复中粘贴：(1) 工作区干净，(2) 本地日志与意图相符，(3) diff stat 无无关文件。
- 绝不提交：机密、凭据、第三方媒体（见 `.gitignore`）或机器特定缓存。发布前跑密钥扫描。
- 布局变更记录在 `docs/MIGRATION.md`（旧 → 新路径表）——历史用 `git mv` 保留。

## 9. i18n 协议

- `docs/` 与根目录 README 三件套以英文为正本。`docs/i18n/zh-CN/` 与 `docs/i18n/ja/` 是译稿；英文源发生实质性变更时同步更新（或明确标注为过期）。
- 产品名、文件路径与协议关键词（N1–N9、C-01–C-18、证据分级）保持不译；翻译行文，不翻译标识符。

## 10. 事故与教训协议

- 事故（通道中断、规则违反、未遂事件、被推翻的论断）以「日期、经过、处置」追加到 `ops/OPS-LOG.md`。被推翻的结论从产物中删除，并在日志中标注 `OVERTURNED: …`。
- 改变行为的教训必须写进*规则*（本文件）或任务书模板——不能只写日志。

## 11. 安全与隐私

- 仓库中永远不放凭据。采集材料中发现的令牌发布前一律脱敏。
- 私有基础设施在公开文档中只作泛化描述；探针证据如嵌入私有端点，仅保留在本地。
- 博物馆图像：仅使用公有领域 / 开放许可来源；署名记录在 `knowledge/INDEX.md` 与图像清单中。

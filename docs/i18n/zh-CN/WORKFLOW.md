## 1. 角色

- **主脑**（顶层 agent 会话）：定方向、切分工作、派发、验收（读产物 + 跑验收条件）、综合汇总，并维护 `ops/GOALS.md`、本文件与 `docs/`。
- **研究工人**（会话内子代理）：只写入各自任务书中给定的**专属路径**。有名字（`agent://<Name>`）；可以互相发消息交叉核对。仅当任务书明确允许时，才可再派只读的子代理。
- **跨 harness 工人**（`dispatch.ps1` —— claude / codex / omp）：体量大、耗时长的进程外工作。流程：`board.py open`（占用写路径）→ 任务书通过 `briefcheck` → 派发 → 读 `last.md` + 核验产物 → `board.py close --verify`。

## 3. LOOP 协议（每条研究线都跑这个循环）

1. 从 `ops/GOALS.md` 取一个 `open` 条目（必须已带产物路径 + 验收条件）。
2. 深度研究：工具不限；**新线索立即以子条目追加到 `ops/GOALS.md`**（新 ID + 产物路径）——绝不丢线索。
3. 在条目路径落盘产物；每条论断都带来源；证据分级 `[自述]/[史料]/[研究]/[归纳]/[推测]`。
4. 自审四段：**A 先行产出**（先落盘一部分，再继续）→ **B 反驳**（尝试推翻自己最强的 3–5 条论断；打 `CONFIRMED/WEAKENED/OVERTURNED` 标签 + 所运行的命令；被推翻的论断从产物中删掉）→ **C 机械验证**（点名一个检查器；粘贴原始输出）→ **D ≤14 行小结**（已确立 / 被推翻 / 未知 / 下一步）。
5. 主脑验收：读产物、跑验收条件；**实现者绝不验收自己的工作**；关键产物由他人复检。
6. 更新 `ops/GOALS.md`（标 done + 新条目入队）→ 用一条消息向 Owner 汇报（结论先行）。

## 4. 写路径纪律

- 一个路径一个写手。冲突由主脑重新切分——绝不绕开。
- 文件名即归属（例如 `knowledge/domains/painters/dossiers/<id>.md` 属于该画家的工人）。
- 原始来源（`knowledge/domains/motion-graphics/origin/`）**只读**。

## 5. 证据标准

- 每条关键论断 = `path + key` 或一个 URL；引文必须可查证（书信 / 访谈 / 博物馆页面）。
- 数字带分母 + 日期；「没找到」≠「不存在」（写「未找到（已查: …）」）。
- 项目立场：「创作原则」是**归纳出的操作规则**，不是对艺术家内心状态的断言；有出处的陈述与 AI 归纳分开标注。

## 6. 工具地图

| 工具 | 用途 |
|---|---|
| `web_search` / `read`(URL) | 通用检索与静态抓取 |
| eval `browser` / chrome-devtools MCP | 重 JS 页面、交互、截图 |
| `task` 子代理 | 进程内研究扇出（有名字、可用 IRC 寻址） |
| `dispatch.ps1` | 跨 harness 派发（claude / codex / omp），派发板 + briefcheck 两道关卡 |
| `sessq` / `archive` | 历史会话与旧测量 |
| `board.py` | 派发记账（open / close / reconcile） |

## 7. 汇报格式（面向 Owner）

首行 = 结论或下一步；多步用编号；每组 ≤5 条；无客套话；给具体时长。

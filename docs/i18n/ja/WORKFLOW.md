## 1. 役割

- **メインブレイン**（最上位のエージェントセッション）：方向づけ、作業の切り分け、ディスパッチ、成果の受け入れ（成果物を読み、受け入れ条件を実行）、統合、そして `ops/GOALS.md`・本ファイル・`docs/` の維持管理を担当します。
- **リサーチワーカー**（セッション内サブエージェント）：ブリーフで与えられた**専有パス**に書き込みます。名前付き（`agent://<Name>`）で、メッセージによる相互クロスチェックが可能です。サブサブエージェントは、ブリーフが読み取り専用の子を明示的に許可した場合に限ります。
- **クロスハーネスワーカー**（`dispatch.ps1`——claude / codex / omp）：大規模で長時間のプロセス外作業。フロー：`board.py open`（書き込みパスを確保） → ブリーフが `briefcheck` を通る → ディスパッチ → `last.md` を読む + 成果物を検証 → `board.py close --verify`。

## 3. LOOP プロトコル（すべてのリサーチラインはこのループを回します）

1. `ops/GOALS.md` から `open` の項目を取ります（成果物パス + 受け入れ条件がすでに書かれている必要があります）。
2. 深いリサーチ：ツールは無制限。**新しい手がかりは即座に `ops/GOALS.md` へサブ項目として追記**します（新しい ID + 成果物パス）——決して捨てません。
3. 項目のパスに成果物を着地させます。すべての主張に出典を付けます。エビデンス等級は `[自述]/[史料]/[研究]/[归纳]/[推测]`（本人の証言 / 史料 / 研究文献 / 帰納 / 推測。識別子は原文のまま）。
4. 自己レビューは 4 部構成です：**A 早期アウトプット**（まず何かを着地させ、それから続けます） → **B 反論**（自分の最強の主張 3〜5 件を覆してみます。`CONFIRMED/WEAKENED/OVERTURNED` タグ + 実行したコマンドを記録。覆った主張は成果物から削除） → **C 機械検証**（チェッカーを 1 つ指定し、生の出力を貼ります） → **D ≤14 行のサマリ**（確定 / 覆った / 不明 / 次）。
5. メインブレインの受け入れ：成果物を読み、受け入れ条件を実行します。**実装者が自分の仕事を受け入れることはありません**。重要な成果物は別の者が再チェックします。
6. `ops/GOALS.md` を更新し（done にして新規項目をキューへ）、オーナーへ 1 通で報告します（結論を先頭に）。

## 4. 書き込みパスの規律

- パスごとに書き手は 1 人。衝突はメインブレインが切り直します——回避して進めてはなりません。
- ファイル名が所有権を表します（例：`knowledge/domains/painters/dossiers/<id>.md` はその画家のワーカーのもの）。
- 生のソース（`knowledge/domains/motion-graphics/origin/`）は**読み取り専用**です。

## 5. エビデンス基準

- すべての主要な主張 = `path + key` または URL。引用は検証可能でなければなりません（書簡 / インタビュー / 美術館のページ）。
- 数値には分母 + 日付を付けます。「見つからない」 ≠ 「存在しない」（「未找到（已查: …）」と書きます）。
- プロジェクトの立場：「創作原則」は**帰納された操作ルール**であり、画家の内面についての主張ではありません。出典に基づく記述と AI による帰納は別々にラベル付けします。

## 6. ツールマップ

| ツール | 用途 |
|---|---|
| `web_search` / `read`(URL) | 一般的な取得と静的フェッチ |
| eval `browser` / chrome-devtools MCP | JS 主体のページ、操作、スクリーンショット |
| `task` サブエージェント | プロセス内のリサーチ・ファンアウト（名前付き、IRC でアドレス可能） |
| `dispatch.ps1` | ボード + briefcheck ゲート付きのクロスハーネス・ディスパッチ（claude / codex / omp） |
| `sessq` / `archive` | 過去のセッションと旧計測値 |
| `board.py` | ディスパッチの記帳（open / close / reconcile） |

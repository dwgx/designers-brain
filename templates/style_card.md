## 卡结构（顺序固定）

1. **任务头（固定句式）**
   `用代码做一支 10 秒的 MG 动画（1920×1080，30 帧），<渲染器>，配乐音效也用代码合成、跟画面卡点；先出 6 张关键帧给我看，再做动画，最后逐帧自查。`
   - `<渲染器>` ∈ 「用 Blender 的 Python 脚本搭场景、渲染」|「网页逐帧渲染」（二选一，写死）
2. **画风段**：`画风：<名字>。<4-8 条可判定规则>`
   - 量化/物理约束：角度、像素、帧率、色数、缓动、过冲幅度、回弹帧数、动作最短时长、同屏颜色数…
   - 规则必须「能被逐帧自查」——形容词换成数字或物理描述
3. **内容段**：`内容：【<10 秒分镜，含结尾落地文案>】`
   - 【】留给用户替换；必须自带一个**可验收的结尾文案**（收尾字/标题）
4. **反约束段**：`别做成：<3-4 条>`
   - 每条封堵一个模型默认退化行为（交叉淡化冒充形变、默认塑料材质、硬阴影、运动模糊滥用、淡入淡出转场、发光字、细字体、半像素位置、互补色、多个强调色…）
   - **v0.3**：每条按「判例式规则格式」（见下节）写，编号 `F1…Fn`；画风段条目适用同一格式（编号 `S1…Sn`，有判例即回填）。

## 判例式规则格式（v0.3 新增；画风段与反约束段适用）

> 来源：vsc handbook §2.6 / §5.1 #1——借 `aesthetic-rules.md` 的判例三要素，「别做成」段由纯禁令升级为判例格式。

每条规则 = **三要素，缺一不可**：

1. **规则**：一句可执行的话（沿用现有写法：量化 / 物理约束，或对模型默认行为的封堵）。
2. **用户原话判例**：触发这条规则的**用户原话**或返工经过（带帧号 / 位置）。判例只能来自真实反馈或实测返工——**不许编造**；新卡暂无判例时写「判例：暂无（命中即回填）」，一旦发生违反 / 返工必须回填，**判例只增不删**。
3. **自检方式**：这条怎么查——机械检查（命令 / 统计量）或逐帧肉眼检查点（帧号位置）。

**配套纪律**：

- **编号只追加不重排**：画风段编 `S1…Sn`、反约束段编 `F1…Fn`；新增条目续号，已发布编号永不复用 / 重排；现有卡升级时按现有条目起编，不回改已发布编号。
- **违反须记录**：可以有意识地违反某条（风格需要），但必须写进该项目的说明文档（写明违反了哪条、为什么）；未记录的违反视为缺陷（评审侧对应 `review_rubric.md` §5「违反须记录」条款）。
- **验收输出**：逐条过一遍，输出 `编号 ✓` 或 `编号 ✗(位置)`（位置 = 帧号 / 画面名）；不许用「整体不错」代替逐条输出。

**格式样例（引自 vsc R3，只学格式；判例原文见 handbook §2.6）**：

```text
规则：节奏宁慢勿快。
判例（用户原话 / 返工经过）：全片六次独立反馈全部指向「放慢 / 停留」，从未有一次「太慢了」的反向反馈；用户：「第一个镜头还是太快了，放慢到3秒」。
自检：把每个镜头当第一次看——哪里没看清？交互段落自己能不能跟着操作一遍？
```

本项目判例回填来源：实验返工记录（`research/experiments/*/checks.md`）、评审记录（`review_rubric.md` 流程）、Owner 反馈——回填时写明日期与帧号。

## 卡 frontmatter（机读层）与「参考实现」指针（v0.3 新增）

> 来源：vsc handbook §2.2–§2.4 / §5.1 #2——卡文件头带 YAML frontmatter 供索引机读；「卡的语义层与实现的参数层显式分离」。

**frontmatter（新卡落盘时写；最小字段集）**：

```yaml
---
name: <卡名 = 文件名 = 落盘 id>
一句话: <手法本体 + 收尾，一句话>
适用: <使用场景>
时长: 300f（10.000s @30fps；分段写法：入场 nf + 主动作 nf + 落定 nf）
能量: <低 / 中 / 中高 / 高（走势说明）>
渲染器: 网页逐帧 | Blender
标签: <类别标签（typography / pixel / line-art / 3d …）>
---
```

- 解析器不依赖键序（逐行 `key: value`）；索引 / 清单从卡重算、不手抄第二份——**产物必须与源同步**：卡改了，引用它的索引与实施清单同步更新（vsc 侧由 sync 脚本 + CI 漂移门强制，本地以自查纪律代替）。

**参考实现指针**：

- 卡跑通后，正文末尾补「参考实现」段：指向实现目录（源码 + 成片 + 自查报告），如 `research/experiments/anim_test_01/`。
- 实现是**参数真相源**：补间数值、缓动、物理常数以实现为准；卡文本给语义、手法本体与调校结论（「已知坑」）。
- 跑通前写「参考实现：暂无（首支成片跑通后回填）」；实现改了而卡没跟上（或反之）= 漂移，必须同步。

## 品牌→动效参数两轴推导（v0.3 新增；需新推一套动效 tokens 时用）

> 来源：vsc handbook §5.1 #6（`pipeline.md` 阶段 1）——「控制参数（弱 / 中 / 强）」升级为两轴推导 + 6 预设；不凭手感挑 easing。

把品牌 / 主题放到两根轴上，从最近的预设起步：

- **能量轴**：低（沉稳 / premium / 机构感）↔ 高（运动 / startup / 娱乐）——决定时长、过冲、squash 幅度；
- **调性轴**：严肃（金融 / 医疗 / enterprise）↔ 活泼（消费 / 社交 / 儿童）——决定路径曲直、次级动作多寡。产品视觉本身是证据（锐利几何形 → 工程感；圆角 + 亮色 → 柔和活泼）；用户口述的品牌词覆盖视觉推断。

| 预设（品类） | 主时长@30fps | 入场 easing | 过冲 | squash |
|---|---|---|---|---|
| 专业信赖（fintech / enterprise / B2B） | ~21f | bezier(0,0,0.2,1) | 1.0 不弹 | 0 |
| 精致高端（奢侈品 / 时尚） | ~48f | bezier(0.4,0,0.6,1) | ≤1.02 | 0 |
| 活力大胆（体育 / 游戏 / startup） | ~18f | bezier(0.16,1,0.3,1) | 1.12 | 0.25 |
| 活泼愉悦（消费 / 社交） | ~27f | bezier(0.34,1.56,0.64,1) | 1.08 | 0.18 |
| 平静关怀（健康 / 教育） | ~42f | ease-in-out 对称 | 1.0 | ≤0.04 |
| 亲和友好（小微 / 社区） | ~26f | bezier(0.25,0.46,0.45,0.94) | 1.04 | 0.08 |

用法：定预设 → 按两轴微调 → tokens 写进项目 spec。**自检两条**：① 用三个词描述成片动效，与品牌词对得上吗；② 同一套 tokens 必须同时管入场 / 转场 / hold 节奏——一个品牌一种动效嗓音，混用两套读作拼盘。预设值与卡内硬判例冲突时**判例赢**（落地要弹的场合 y1 必须 >1；「不弹」指无落地隐喻的淡入 / 推移类动作）。

## 输出规格块（v0.2 新增：粘进提示词的交付物清单）

> 来源：仓库 `template.md`「Output (fixed)」段 + `prompts/*.md`「Deliver」段（raw 直读 2026-10-15）。

```text
# Output (fixed)
- 1920×1080, 30 fps, exactly 10.000 s (300 frames), H.264 MP4 with stereo AAC audio (48 kHz),
  mastered to −14 LUFS integrated, true peak ≤ −1 dBTP. Final file: video.mp4.
- 验收帧号：每张卡在实施计划里写死 2 个验收帧号（覆盖动作峰值与文字锐度 / 穿帮风险点）；完成即渲静帧肉眼验收
  （构图 / 穿帮 / 文字锐度）后才算完成；静帧按迭代版本归档 checks/qa/，用户贴帧反馈时可直接对号。
- Deliverables: video.mp4 ｜ 6 keyframe stills + 3×2 contact sheet ｜ cue sheet（beats & hit times，音画同表）｜
  full source ｜ CREDITS.md（每项素材的来源与许可）｜ self-check report（命令 + 结果）｜
  short report（概念两句话 + 每条画风规则的落点 + 自评 top-3 弱点）。
```

- 卡内声明了别的规格（像素卡内部 320×180、竖屏 1080×1920、24 fps…）以卡内为准；「exactly 10.000 s」与响度/真峰两条不放松（验收口径，对应评审表的 spec 检查）。
- 验收帧号口径（vsc §3.4）：「2 个写死帧号」是**实施计划纪律**；「每镜头至少入场中 / 动作峰值 / 落定后三帧」是**抽帧口径**——两者不冲突，引用时别混。与 6 关键帧流程并用：6 帧 = 开工前的人评门槛，2 帧号 = 实施期的完工纪律。
- 缺 CREDITS.md 或缺自查报告 = 未交付。

## 确定性条款（v0.2 新增）

> 来源：仓库 `prompts/*.md` Rules 段（原文）+ `harness/render.mjs` 文件头契约（compare §3.1）；展开版（≥6 条）与命令清单 → `templates/determinism_contract.md`。

任务头之后（或 Rules 段）固定粘一条，防止「同一提示词每次出片不同」：

```text
Rendering must be deterministic: every frame is a pure function of time t. Seeded randomness only; physics and
particles precomputed or closed-form; no real-time clocks; no state-triggered CSS transitions. A reliable route:
a web page that can draw any time t on request, captured frame by frame with a headless browser and encoded with
ffmpeg (or a Blender script that renders a PNG sequence).
```

- 网页路线等价物：页面暴露 `window.renderAt(t)`（纯函数）+ `window.DEMO = {width,height,fps,duration}` + `window.__ready`；
- Blender 路线等价物：物理先算成数据文件（npz/events.json），脚本渲 PNG 序列；
- 条款全文与自查命令 → `templates/determinism_contract.md`（本模板配套件）。

**两跑一致（v0.3 明确化 → 逐帧 SHA256 对比条款）**：判定口径 = **同一帧渲两遍，逐帧 SHA256 全等**——第二遍必须**乱序 / 倒序抽帧重渲**（防跨帧状态泄漏），两遍输出逐帧比对 SHA256，全等才算通过；不通过先修非确定性源（实时钟 / 未播种随机 / 跨帧状态残留），不许把不一致说成完成。可直接追加进提示词的一句：

```text
两跑一致：同一帧渲两遍（第二遍乱序重渲），逐帧 SHA256 全等才算通过；不通过先修非确定性源。
```

（实测依据：B-07——同序重渲漏掉跨帧状态泄漏，乱序才暴露，f0150 差 158 源像素；工具 `python checks/selfcheck.py`；展开见 `determinism_contract.md` §3 ①b。全片两跑用 `psnr / ssim` 兜底（期望满分）；同机同参下逐字节成立，跨机器 / 跨浏览器版本不承诺。）

## 评审步骤（v0.2 新增）

> 来源：仓库 `rubric.md` 两段式（「制作 → 独立评审 → 按评审修改 → 再评审」）；改编版评审表 → `research/agent-art/cards/review_rubric.md`。

1. **独立评审**：成片后另开一个 AI 会话，给它成片路径 + 本卡提示词，按 `review_rubric.md` 打分（7 维 1-10，目标 ≥9，Do not inflate）并出 5-10 条带时码的修复清单；
2. **修改轮**：把评审贴回制作会话 → 先存版本 N → 逐条落实（可用更好的做法替换，须说明理由）→ 重渲复核 → 报告落实/跳过清单；
3. critical 旗标一票先修：generic/AI-template、中文文案不自然、fallback 字体/豆腐块、spec 失败。
4. **交付前「干净上下文终检」（v0.3 新增）**：派独立子代理（干净上下文；不给制作过程理由 / 修改历史 / 预期结论），按 `review_rubric.md` §5 协议出**带帧号证据**报告（7 维分组）；**必须修复项清零才算交付**。制作者自查 ≠ 终检——首检永不直接交给用户。

## 「先出 6 关键帧」的落地方式（v0.2 新增，--stills 式）

> 来源：仓库 `harness/render.mjs` CLI（`--stills 0.5,2,4.25` → `out/stills/`）+ `research/agent-art/html/workflow.md` §4。

- 锚点帧（10 s / 30fps）：`0 / 45 / 90 / 150 / 225 / 285`（= 0 / 1.5 / 3 / 5 / 7.5 / 9.5 s）；**最后一帧必须含收尾文案**（一帧可核对的验收锚点）。
- 只实现 seek() 的 6 个关键状态（不做补间）→ 渲 6 帧 → 拼 3×2 contact sheet 交人看 → **通过后才做全片**；不过就改 seek() 重渲，不许改截图糊弄。
- 命令行等价物：
  - 仓库 harness 式：`node harness/render.mjs <demo> --stills 0,1.5,3,5,7.5,9.5`；
  - 本地骨架式（workflow §4）：`render.js --keys` + `KEY = [0,45,90,150,225,285]`。
- 拼图命令（本机实测 2026-10-15）——**关键帧落盘就用连续编号**（k0.png…k5.png，或渲后重命名成连续序号）：

  ```bash
  ffmpeg -framerate 1 -i key/k%d.png -vf "tile=3x2:padding=8:color=#101010" -frames:v 1 key/keyframes_sheet.png
  ```

- 注意：workflow §4 写的 `-i key/k%04d.png` 对不连续帧号（k0000/k0045/…）**只读到第 1 帧**（本机 ffprobe `nb_read_frames=1`，拼出 1 格图）；替代 = 连续编号，或 concat 清单（`ffmpeg -f concat -safe 0 -i list.txt -vf "tile=3x2:padding=8:color=#101010" -frames:v 1 sheet.png`，实测可用）。本机 ffmpeg（n9.0.1）**不支持 `-pattern_type glob`**（"globbing is not supported by this libavformat build"）——glob 方案别用。

## 填写规则

- 先 6 关键帧 → 再动画 → 后自查：**三段流程不许合并**（这是 15 卡的骨架纪律）。
- 反约束每条都要对上一个「模型默认行为」；不对着默认行为的禁令是空话。
- 反约束与画风段按判例式格式写（`F#` / `S#` 编号只追加；有判例即回填）；跑通后补「参考实现」指针。
- 内容段结尾文案 = 验收锚点（一帧能核对的东西）。
- 渲染器二选一：3D/物理/材质 → Blender；2D/排版/WebGL 特效 → 网页逐帧。
- 新卡落盘路径：`research/agent-art/cards/cards/<id>.md`（本模板复制后填写；带 frontmatter 机读层）。

- **N3 轴所有权表**：组合卡必须附 `轴名 | 持有模块 | 对方在该轴上的规则处置（删除/降档/分区）`；① 每轴只有一个持有者；② 辅模块在冲突轴上的 §8.2 规则**整条移除**（§8.2 是判分规则，不是强度旋钮）；③ 未列入表的轴默认无冲突。
- **N6 色数计数口径**：色数上限只约束**平涂色块层**；金属/金箔/高光材质层单列，不计入色数，但面积 ≤5% 画面、且必须在卡内声明。
